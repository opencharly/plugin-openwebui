**Two decisions worth naming.**

1. **`apply` uses the per-surface typed endpoints, never the bulk import.** Upstream's
   `POST /api/v1/configs/import` is untyped, runs no per-surface side effect (model-cache
   invalidation, tool-server re-registration, MFA session revocation), and reaches its write
   through a helper named `update_mfa_config` — an accidental coupling, byte-identical in
   0.12.3 and 0.13.3, that a release could remove without notice. The per-surface POSTs
   validate the payload (422) and run the side effect. `export` still reads the raw table,
   because a backup should be complete rather than typed.
2. **A credential never enters the entity, and redaction is shape-preserving.** `save` writes
   `{keep: true}` placeholders — a redacted `OPENAI_API_KEYS` LIST stays a list of
   placeholders — so the entity the CLI writes always passes the schema it serves, and
   save→apply is a no-op. A non-empty literal credential is refused by `apply` unless
   `--allow-literal-secrets`; an EMPTY one round-trips (a server with no key configured
   answers `""`).

**Three defects the live run found (fake could not).** `banners` answers GET with a bare list
while accepting `{"banners": [...]}` on POST; `chats` gained fields in 0.13.3 and the four
`SUBAGENTS_MAX_*` limits answer `null` on a fresh deployment; and an empty credential in a
credential-named field was being refused. All three are fixed in this head and covered by
`live_test.go`, which is the mechanism that found them.

the surface's own GET shows the new value), plus the round-trip invariant.
