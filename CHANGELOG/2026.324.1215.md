# 2026.324.1215 — fix(openwebui-cli): follow Open Web UI 0.13.4's connections form

## Summary

Follows Open Web UI 0.13.4's connections form. 0.13.4 removed Direct Connections and Direct
Integrations, and its `ConnectionsConfigForm` now carries only `ENABLE_BASE_MODELS_CACHE`
(`routers/configs.py`, verified in the 0.13.4 wheel). The plugin's `#Connections` schema still
required `ENABLE_DIRECT_CONNECTIONS`, so `save` failed to validate the server's GET body:

```
charly: error: entity fails #OpenwebuiInput: #OpenwebuiInput.config.connections.ENABLE_DIRECT_CONNECTIONS: field is required but not present
```

and the disposable bed's read-back (`openwebui-plugin-present`) could not run.

- `candy/plugin-openwebui/schema/openwebui.cue` — `#Connections` drops the two removed
  switches; `ENABLE_BASE_MODELS_CACHE` stays required, so the required-field control still bites.
- The fixtures, README and CLI skill drop the removed names; `cue fmt` collapses the remaining
  field's alignment.

This was found by the R10 bed in the consumer change: opencharly/distro-cachyos ran
`check-openwebui-pod` against the Open Web UI 0.13.4 feat SHA, and its first run failed exactly at
the plugin read-back.
